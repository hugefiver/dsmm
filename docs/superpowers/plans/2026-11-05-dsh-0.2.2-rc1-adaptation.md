# DSH 0.2.2-rc.1 适配说明

## 支持范围

DSMM 同时支持 DSH `0.2.1-rc.2` 与 `0.2.2-rc.1`，支持声明为：

```text
>=0.2.1-rc.2 <0.2.2-0 || >=0.2.2-rc.1 <0.3.0
```

包版本和开发依赖保持不变。后续 Host 版本仍需按实际接口验证；声明范围不代表所有预览版本均已实测。执行、取消、审批、完成投递与会话存储继续由原生 Host 管理。

## 模型路由

- rc.1 在提示词、工具能力和请求准备之前确定模型；请求阶段拒绝与固定选择冲突的路由，不发送错误请求。
- native root 保留原生模型选择；configured root 与委派子任务使用各自已准入的配置。冷恢复采用当前配置，已有子任务不继承父会话后续增加的权限。
- 配置 effort、原生显式 effort 与适配器默认值保持区分。同路由重试保留失败请求的有效参数；fallback 使用其完整参数集合，不混入 primary 专属参数。
- 两代 Host 均保留有界同路由重试。rc.1 不支持同一步内跨路由 fallback；rc.2 保留原有切换能力。
- 配置切换、取消和运行实例退休后，失效请求与历史授权不得继续执行。

## 实时委派信息

前台委派结束前可通过只读观察流获取角色、level、初始路由和实际请求路由，包含 provider、model 与已报告的 reasoning effort。

- 实际路由仅来自本次子任务自身的请求证据；缺失或失效时显示 unknown，缺失 effort 显示未报告。
- 会话、调用与运行生命周期隔离；终态证据冻结。重复调用 ID 不阻止执行，无法可靠区分的实时观察降级为 unknown，各次结果仍绑定自身子任务。
- 断线、重连和鉴权失效不恢复旧的 active 实际值；有明确终态的结果保留其真实证据。
- 子会话支持只读观察，不扩大控制权限。关闭观察不取消子任务，也不改变原生投递次数。
- 观察信息不包含提示词、凭据、任意 headers 或附加执行参数。

## 文件与临时目录

DSMM 默认启用原生文件观察保护，保留既有文件的先读后修改及版本冲突检查；用户 profile 的显式覆盖仍有优先级。

rc.1 原生多文件补丁通过 `tool-fs.config.applyPatch: true` 显式启用，默认关闭。角色只读限制、继承工具上限、原生 deny/never、取消及文件沙箱继续有效。预检失败不写入；提交顺序执行，后续操作失败或取消可能保留此前成功的修改。rc.2 不提供替代补丁引擎。

临时目录使用所选 DSH mode/backend 的完整默认许可范围，不另行限制为专用 `temp/dsh`。文件工具与 Windows 子进程的临时目录范围可以不同；临时目录可写不授权删除无关文件，也不免除独立权限检查。

## 请求头与模型校准

rc.1 的标准及 raw Pi-AI 请求保留原生动态请求头能力、原生 attribution 和凭据来源。请求头处理失败时不发送推理请求；取消、配置变化与退休仍使失效请求被拒绝。DSMM 不新增业务 headers 或路由级认证配置；rc.2 保持原有行为。

明确具有 Gemini 4 身份的模型统一加载现有专属校准，包括 `gemini-4.x`、`gemini-4.x-pro`、`gemini4`、数值 minor 及 `@default`、`:latest` 后缀。裸 `4.x` 不自动归类 Gemini，wildcard 不声明精确版本。角色层顺序、单次加载和 Deepwork 关闭行为保持一致。

## 网络与未开放能力

rc.1 缺少 DNS 应答级地址策略的公开接入点。配置本地地址 deny 时，无法验证目标的直接请求保持拒绝；rc.2 的 resolver、pinning 与 NAT64 地址检查不变，不接管 Host 的全局网络策略。

同 activation 前台转后台、运行中配置 Apply、通用长期 grants、额外目录授权系统、细粒度沙盒开关及 Schannel 证书扩展均未开放。证书扩展的后续目标是在底层支持且验证有效时默认启用并可独立关闭；TLS 校验始终保留。

## 验证与未覆盖项

构建、严格 TypeScript 编译及 rc.1 SDK 声明检查通过。隔离测试使用新构建产物、独立配置与会话、任务专属目录、loopback 模型端点和虚构凭据。

- rc.1 Host 与补丁权限回归：33/33 通过。
- rc.1 真实 CLI/Gateway 实时委派验收：1/1 通过，覆盖完成前观察、关闭观察后继续执行及重复调用 ID。
- rc.1 请求头产物集成：10/10 通过。
- rc.2 集成主入口：16 通过、3 项能力跳过；请求头子套件 9 通过、1 项不适用。
- 实时观察、RPC、路由比较、组件及 Gemini 校准的定向测试通过；无已知未解决的产品或协议缺陷。

真实浏览器 WebSocket、DOM 和调用卡视觉验收未覆盖，浏览器用例因缺少 Playwright 锚点跳过。真实外部模型、NAT64 实网、外部语言服务器、代表性旧历史样本及 Windows Schannel 仍需各自的验证。未更新运行中的 GUI 或 Host，也未验证安装、发布或非 Windows 平台。
