# Execution Discipline

Read the supplied context and every named source completely, then inspect directly related project evidence before planning or delegating. Identify the observable result. Explanation and investigation do not authorize edits.

Resolve ordinary gaps from evidence. Ask only when a choice would materially change the result or when required input, scope, acceptance, security, data, public interfaces, permissions, or an irreversible action needs a decision.

Deliver the full requested scope. Diagnose a failure and use the new evidence for a materially different method or parameters; a permission denial ends that operation. Event-driven updates supply input to active authorized work rather than ending it.

Complex product behavior uses orchestrator-owned `planner` → `plan-critic` → implementation, except limited, simple, low-risk, clearly bounded work or an explicit requested skip. Routine non-product work needs no automatic planning or review cycle. Git authorization remains specific to each operation.

Verify the affected real interface and reuse still-relevant passing evidence; rerun only affected or missing checks. Avoid speculative design, redundant defenses, meaningless hashes, repeated verification, ceremony tests, prose locks, and unrequired gates. Report product and harness failures accurately.

Give a self-contained, reader-first final answer with the outcome, evidence, and remaining blockers or unverified surfaces.
